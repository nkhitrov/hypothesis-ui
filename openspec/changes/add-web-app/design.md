# Design

## Context

Репозиторий свежий: python-пайплайн удалён (baseline в git-истории), остались `map.yaml` (демо-карта — источник схемы и seed) и `README.md`. Приложение пишется с нуля как статический SPA. Ключевое ограничение из исследования: рантайм без сети (CDN в изолированных браузерах не грузится — проверено на практике), поэтому все зависимости в бандле.

## Goals / Non-Goals

**Goals:**
- Автоматическая раскладка карточек из модели (никакого ручного перетаскивания) — порт проверенного алгоритма из удалённого `renderer_cards.py`.
- LLM-цикл правок без визуального редактора: экспорт → правка → импорт, плюс встроенный текстовый редактор модели.
- Хостинг «положил dist/ на любой статический сервер — работает».

**Non-Goals:**
- Визуальный редактор карточек мышью (добавление/перетаскивание карточек на доске) — модель правится текстом.
- Сервер, аккаунты, синхронизация между устройствами.
- Экспорт в PNG/Mermaid, тёмная тема, несколько топологий — кандидаты в будущие change'ы.

## Decisions

### D1. Стек: Vite + React + TypeScript (strict)
Рацио: пользователь явно выбрал полноценное веб-приложение; React даёт дешёвую композицию видов (доска/список/редактор), TS strict ловит ошибки схемы на этапе сборки. Альтернативы: vanilla TS (больше ручного UI-кода при том же результате), Svelte (меньше экосистема). Сборка Vite → статика без CDN.

### D2. Схема данных — прямой перенос `map.yaml` в TypeScript-типы
Сущности и поля 1:1 с прежней моделью (см. capability `map-model`): демо-карта конвертируется в `seed.ts` без изменения смысла. Альтернатива — взять схему HypoMap-спецификации — отклонена: она заброшена и беднее (нет блокеров, статусов, затрат).

### D3. Раскладка: детерминированные абсолютные координаты, вычисляемые из модели
Колонки «цель+метрики | субъекты | гипотезы | задачи | блокеры»; высота карточки оценивается по переносу строк (константы ширины символа и межстрочного интервала); стрелки — SVG-безье между якорями карточек. Так раскладка воспроизводима и не требует графовой библиотеки; альтернатива (dagre/ELK) даёт «спагетти» и тяжёлую зависимость. Проверено черновиком `renderer_cards.py` (удалён, порт в `src/model/layout.ts`).

### D4. Хранение: localStorage, ключи `hymap:index` и `hymap:map:<id>`
localStorage достаточно (карты — килобайты JSON), синхронный API упрощает код; IndexedDB дал бы асинхронность без выгоды при таких объёмах. Индекс — список `{id, title, updatedAt}`; тело карты — целиком под своим ключом. При исчерпании квоты — понятная ошибка пользователю.

### D5. Форматы: JSON нативно, YAML через `js-yaml`
`js-yaml` — единственная рантайм-зависимость кроме React; детект формата: пробуем JSON.parse, при неудаче — YAML. Экспорт: YAML по умолчанию (читаемее для LLM), JSON — переключатель.

### D6. Состояние приложения: один корневой React-стейт + хук `useMapStorage`
`App` держит `{maps: MapIndex, currentId, view}`; хук инкапсулирует чтение/запись localStorage и версии схемы (`schemaVersion: 1` в теле карты — задел на миграции). Редактирование модели — только через «применить текст»/импорт (нет инкрементальных правок полей), поэтому сложный стейт-менеджер не нужен.

### D7. Валидация — единый модуль, используемый всеми входами
`src/model/validate.ts` вызывается из импорта, текстового редактора и первого запуска; возвращает список ошибок строками — их видят UI-компоненты и они же — критерии приёмки.

## Risks / Trade-offs

- [Оценка высоты карточек разъедется с фактической вёрсткой] → допуск в константах; якоря стрелок по центрам, расхождение в пиксели незаметно; при необходимости — замер `getBoundingClientRect` после монтирования и коррекция позиций (не требуется по спеке).
- [localStorage недоступен (приватный режим/квота)] → приложение работает с картой в памяти, показывает предупреждение «данные не сохраняются», импорт/экспорт остаётся каналом сохранности.
- [Русские тексты в `id`/файлах у сторонних пользователей] → валидатор требует строковые id, но не ограничивает алфавит; имя экспортного файла — из названия карты с санитизацией.
- [Рост числа связей гипотеза→метрика захламляет дугами] → пунктир и приглушённый цвет; если станет проблемой — фильтр связей (будущий change).

## Migration Plan

Первый выпуск: чистая установка. Откат — предыдущий коммит git. Данные python-эпохи (`map.yaml`) конвертируются в демо-карту seed'а и больше нигде не используются; файл удаляется после конвертации.

## Open Questions

- Нужно ли когда-нибудь Several карт в одном файле импорта (портфель)? — отложено: формат одной карты; расширение массивом не ломает схему.
