# Spec Delta

## Purpose
Обмен данными карты с внешним миром: импорт и экспорт в форматах JSON и YAML — канал для правок через LLM, совместной работы и резервных копий.

## ADDED Requirements

### Requirement: Экспорт карты
Приложение SHALL экспортировать текущую карту в файл `.json` или `.yaml` и в буфер обмена. Имя файла основано на названии карты. Экспортированный файл содержит полную модель и при повторном импорте восстанавливает карту без потерь.

#### Scenario: Экспорт и повторный импорт
- **WHEN** карта экспортирована в YAML, файл изменён во внешнем редакторе (например, LLM) и импортирован обратно
- **THEN** карта в приложении равна содержимому файла после прохождения валидации

### Requirement: Импорт из файла
Приложение SHALL принимать файлы `.json` и `.yaml` через выбор файла и перетаскивание, автоматически определять формат по содержимому.

#### Scenario: Drag&drop YAML-файла
- **WHEN** пользователь перетащил в окно валидный YAML-файл карты
- **THEN** открывается диалог импорта: создать новую карту или заменить текущую

### Requirement: Валидация при импорте
Импорт SHALL отклонять невалидные данные с полным списком ошибок валидации; существующие карты пользователя при этом не изменяются.

#### Scenario: Файл с битой ссылкой
- **WHEN** импортируется файл, где задача ссылается на несуществующую гипотезу
- **THEN** импорт отклоняется, показана ошибка с id задачи и гипотезы, текущие карты не тронуты

#### Scenario: Файл не является картой
- **WHEN** импортируется произвольный JSON без обязательных сущностей
- **THEN** импорт отклоняется с понятным сообщением о несоответствии схеме

### Requirement: Импорт как новая карта или замена
При валидном импорте пользователь SHALL выбирать: создать новую карту или заменить текущую. Замена не удаляет остальные карты.

#### Scenario: Импорт в новую карту
- **WHEN** при импорте выбрано «создать новую»
- **THEN** в списке появляется новая карта с данными файла, текущая не изменена
