# Spec Delta

## Purpose
Правила целостности модели карты гипотез по стандарту 1.2 (docs/knowledge-base): любая операция над картой (импорт, применение текста, создание, рендер) либо проходит проверку, либо отклоняется с человекочитаемым списком всех найденных проблем сразу. Нелегальную связь невозможно ни применить, ни импортировать, ни отрисовать.

## ADDED Requirements

### Requirement: Уникальность идентификаторов
Система SHALL отклонять карту, в которой `id` любой сущности повторяется, и указывать оба конфликтующих элемента в сообщении об ошибке.

#### Scenario: Дубликат id
- **WHEN** задача и гипотеза имеют одинаковый `id` `x1`
- **THEN** валидация возвращает ошибку «дубликат id 'x1'» с указанием типов обеих сущностей

### Requirement: Целостность и типизированность ссылок
Все ссылки между сущностями MUST указывать на существующие `id` ДОПУСТИМОГО типа: `task.hypothesis` — на гипотезу; `hypothesis.target` — на субъект, его боль/желание, метрику или цель (бессубъектный контур); `hypothesis.metrics[]` — на метрику (внутреннюю или отдельную); `subject.goals[]` — на цель; `subject.metrics[]` — на метрику; `motivation.subject` — на субъект; `separatedMetric.goalRef` — на цель; `blocker.blocks` — на задачу. Каждая битая или типически недопустимая ссылка отражается отдельной строкой ошибки с перечнем допустимых типов.

#### Scenario: Задача ссылается на удалённую гипотезу
- **WHEN** задача `t1` ссылается на гипотезу `h9`, которой нет в карте
- **THEN** валидация возвращает ошибку вида «задача 't1': ссылка на несуществующий id 'h9'»

#### Scenario: Гипотеза указывает на задачу
- **WHEN** `hypothesis.target` ссылается на `id` задачи
- **THEN** валидация возвращает ошибку с указанием, что допускается только субъект / мотивация / цель

### Requirement: Запрет связи задача→цель
Система SHALL отклонять карту, в которой задача связывается с целью (`task.goalRef` или эквивалент): задачи ведут только на гипотезы. Переход из масштабной задачи в цель уровнем ниже оформляется многоуровневой картой — отдельной дочерней картой и структурной связью `task.childMapId`, а не стрелкой.

#### Scenario: Задача со ссылкой на цель
- **WHEN** задача содержит поле `goalRef`
- **THEN** валидация возвращает ошибку «связь задача→цель запрещена — задачи ведут только на гипотезы»

#### Scenario: Старые поля многоуровневости
- **WHEN** цель содержит удалённые поля `level`/`parentTask`
- **THEN** валидация возвращает ошибку с подсказкой о `task.childMapId` и отдельной дочерней карте

### Requirement: Вынесенные метрики не обходятся
Если у цели есть вынесенные метрики (хотя бы одна), цель принимает связи ТОЛЬКО через свои метрики: каждый субъект этой цели MUST быть привязан хотя бы к одной метрике этой цели (`subject.metrics[]`), а бессубъектная гипотеза MUST указывать на метрику (`hypothesis.target`), а не на цель. Ссылки `subject.metrics[]` MUST указывать на существующие метрики целей самого субъекта.

#### Scenario: Субъект привязан к цели с вынесенными метриками
- **WHEN** субъект ссылается на цель, у которой есть отдельные метрики, но не ссылается ни на одну из них
- **THEN** валидация возвращает ошибку с перечнем метрик цели и подсказкой привязать субъекта к метрикам

#### Scenario: Бессубъектная гипотеза указывает на цель с вынесенными метриками
- **WHEN** `hypothesis.target` указывает на цель, у которой есть отдельные метрики
- **THEN** валидация возвращает ошибку с подсказкой привязать гипотезу к метрике, а не к цели

#### Scenario: Субъект ссылается на метрику чужой цели
- **WHEN** `subject.metrics[]` содержит метрику, чья цель не указана в целях субъекта
- **THEN** валидация возвращает ошибку о чужой цели метрики

### Requirement: Иерархия целей
`goal.parent` MUST указывать на существующую цель; цепочка родителей MUST быть ацикличной (включая запрет на самоссылку). Разложенная цель (есть под-цели) не принимает прямых связей: субъекты привязываются к под-целям (`subject.goals`), гипотезы — к под-целям или субъектам под-целей, вынесенные метрики (`metrics[].goalRef`) — к под-целям; прямое нарушение — ошибка с подсказкой. Встроенные метрики разложенной цели допустимы.

#### Scenario: Битая ссылка parent
- **WHEN** у цели `parent` указывает на несуществующий id
- **THEN** валидация возвращает ошибку «цель (parent): ссылка на несуществующий id»

#### Scenario: Цикл в иерархии
- **WHEN** цели образуют цикл по `parent` (A → B → A)
- **THEN** валидация возвращает ошибку «цикл в иерархии целей» с перечислением цепочки

#### Scenario: Субъект на разложенную цель
- **WHEN** субъект ссылается на цель, у которой есть под-цели
- **THEN** валидация возвращает ошибку с подсказкой привязать субъект к под-целям

#### Scenario: Гипотеза в разложенную цель
- **WHEN** `hypothesis.target` указывает на цель с под-целями
- **THEN** валидация возвращает ошибку с подсказкой привязать гипотезу к под-цели

#### Scenario: Вынесенная метрика разложенной цели
- **WHEN** отдельная метрика имеет `goalRef` на цель с под-целями
- **THEN** валидация возвращает ошибку с подсказкой привязать метрику к под-цели

### Requirement: Вынесенная мотивация не обходится
Если у субъекта вынесены боли/желания (хотя бы одна), гипотезы MUST привязываться к ним (`hypothesis.target` = мотивация), а не к субъекту напрямую.

#### Scenario: Гипотеза указывает на субъекта с вынесенной мотивацией
- **WHEN** `hypothesis.target` указывает на субъекта, у которого есть отдельные боли/желания
- **THEN** валидация возвращает ошибку с перечнем мотиваций и подсказкой привязать гипотезу к ним

### Requirement: Полнота гипотезы
Гипотеза MUST иметь непустые все четыре части формата «Если—то—потому что—тогда» и цель воздействия (`target`). Список `metrics` MAY быть пустым: метрики влияния часто выбираются позже цели (на доске — плашка «нужно заполнить»); заданные в нём ссылки валидируются как обычно.

#### Scenario: Гипотеза без части «потому что»
- **WHEN** у гипотезы поле `because` пусто
- **THEN** валидация возвращает ошибку с указанием гипотезы и имени пропущенной части

#### Scenario: Гипотеза с ещё не выбранными метриками
- **WHEN** у гипотезы список `metrics` пуст
- **THEN** валидация проходит (метрики влияния — не обязательное поле раннего этапа), на карточке гипотезы показывается плашка «нужно заполнить»

### Requirement: Задачи, метрики и мотивация
Каждая задача MUST быть привязана к гипотезе; `task.group` (если задан) MUST быть непустой строкой; каждая метрика (внутренняя и отдельная) MUST иметь значения `current` и `target`; отдельная метрика MUST иметь `goalRef` и `influence` (влияние относительно цели); каждая вынесенная боль/желание MUST иметь `kind` (pain|wish), описание, `subject` и `influence` (влияние относительно субъекта).

#### Scenario: Задача без гипотезы
- **WHEN** задача не содержит ссылку `hypothesis`
- **THEN** валидация возвращает ошибку «задача не привязана к гипотезе»

#### Scenario: Пустое название направления
- **WHEN** у задачи `group` — пустая строка или пробелы
- **THEN** валидация возвращает ошибку «'group' должен быть непустым названием направления»

#### Scenario: Метрика без целевого значения
- **WHEN** у метрики поле `target` пусто
- **THEN** валидация возвращает ошибку с указанием метрики и имени поля

#### Scenario: Боль с битой ссылкой на субъекта
- **WHEN** мотивация ссылается на несуществующий субъект
- **THEN** валидация возвращает ошибку с указанием мотивации и id

### Requirement: Невалидная карта не рендерится
При наличии ошибок валидации система SHALL отказывать в отрисовке доски: показывается полноэкранная страница со списком всех проблем; доска (карточки и стрелки) не создаётся.

#### Scenario: Хранилище содержит невалидную карту
- **WHEN** загружена карта с запрещённой связью
- **THEN** вместо доски отображается полноэкранный список ошибок; узлы доски отсутствуют

### Requirement: Единственный отчёт об ошибках
Валидация SHALL возвращать список всех нарушений сразу, а не прекращаться на первом; пустой список означает валидную карту.

#### Scenario: Карта с несколькими проблемами
- **WHEN** карта содержит дубликат id и две битые ссылки
- **THEN** отчёт содержит три ошибки, сгруппированные по сущностям
