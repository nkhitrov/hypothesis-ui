# Spec Delta

## Purpose
Редактирование модели карты как текста (YAML или JSON) внутри приложения — мост для правок, подготовленных LLM или вручную, без визуального редактора карточек.

## ADDED Requirements

### Requirement: Двусторонний текстовый вид модели
Приложение SHALL показывать модель текущей карты как текст в выбранном формате (YAML по умолчанию, переключение на JSON), синхронизированный с картой на момент открытия редактора.

#### Scenario: Открытие редактора
- **WHEN** пользователь открывает панель текстового редактора
- **THEN** в ней отображается YAML текущей карты, эквивалентный её модели

### Requirement: Применение с валидацией
Применение текста SHALL парсить его и валидировать: при успехе — модель карты и доска обновляются, происходит автосохранение; при ошибках — изменения не применяются, показывается список ошибок с позициями в тексте, где удалось определить.

#### Scenario: Успешное применение
- **WHEN** пользователь добавил в YAML новую задачу, связанную с существующей гипотезой, и нажал «Применить»
- **THEN** задача появляется на доске в колонке задач, карта сохранена

#### Scenario: Синтаксически битый YAML
- **WHEN** текст содержит ошибку отступа
- **THEN** изменения не применяются, показано сообщение парсера со строкой ошибки

#### Scenario: Логическая ошибка модели
- **WHEN** текст валиден синтаксически, но новая задача ссылается на несуществующую гипотезу
- **THEN** изменения не применяются, показана ошибка валидации «ссылка на несуществующий id»

### Requirement: Откат несохранённых правок
Редактор SHALL позволять откатить несохранённые правки к последнему применённому состоянию модели.

#### Scenario: Откат
- **WHEN** пользователь изменил текст, не применял и нажал «Откатить»
- **THEN** редактор возвращается к тексту, соответствующему текущей модели карты
