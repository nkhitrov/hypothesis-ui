# AGENTS.md — правила для LLM-агентов в этом репозитории

Проект — веб-приложение «Карта гипотез» (Vite + React + TS, доска на React Flow).
Любая правка модели карты, валидаторов, раскладки или демо-данных ОБЯЗАНА
соответствовать методологии. Источник истины — вендоренная база знаний:

1. **Скилл**: `docs/knowledge-base/sociotech-ai-skills/hypothesis-mapping/SKILL.md`
   (+ `references/`) — загружай и следуй ему при создании/правке карт.
2. **Стандарт 1.2**: `docs/knowledge-base/sociotech-ai-skills/hypothesis-mapping/references/standard-1.2.md` — направления связей, шаблоны элементов, цвета.
3. **Топологии**: `docs/knowledge-base/hypothesismapping/topology.md` и `references/topologies.md`.

Ключевые правила (кратко, полные — в стандарте):

- Каноническая топология: `Задача → Гипотеза → Субъект → Цель`.
  Допустим бессубъектный контур: `Задача → Гипотеза → Цель`.
  **Никаких связей задача→цель**: переход задачи в цель уровнем ниже — отдельная
  дочерняя карта + структурная связь (`task.childMapId`), не стрелка.
- Мотивация на отдельном уровне: `Гипотеза → Боль/Желание → Субъект`
  (влияние мотивации — относительно субъекта). Если у субъекта вынесена мотивация
  (даже одна), гипотезы привязываются ТОЛЬКО к его болям/желаниям, не к субъекту.
- Метрики на отдельном уровне: `Субъект → Метрика → Цель` — субъект привязывается
  к вынесенным метрикам (`subject.metrics`), не к цели; влияние метрики — относительно цели.
  Если у цели вынесена хотя бы одна метрика, ВСЕ связи (субъекты и бессубъектные
  гипотезы) идут только к метрикам этой цели. Связь гипотеза↔метрика — структурная
  (поле `hypothesis.metrics`), стрелкой не рисуется.
- Размеры карточек фиксированы содержимым (описание + строки); под стрелки
  карточки не растягиваются. Раскладка — фиксированные колонки по типам
  сущностей (пустые скрыты) с единым отступом; зазоры под стрелки
  не подстраиваются.
- Приоритет (цифра 1–3) ставится относительно соседа слева и красит исходящую стрелку:
  высокий — толстая красная, средний — жёлтая, низкий — тонкая зелёная.
- Цвета элементов не менять: цель/метрика `#cadf58`, субъект/мотивация `#ffc831`,
  негативный субъект `#ffb373`, гипотеза `#ffef73`, задача `#a6cdff`, блокер `#FFA391`.
- Гипотеза — формат «Если — то — потому что — тогда», все четыре части непустые;
  «потому что» опирается на мотивацию субъекта, «тогда» — на метрики цели.
- Валидация (`src/model/validate.ts`) — единый список всех нарушений; невалидная карта
  не рендерится (полноэкранная ошибка). Новые правила — сначала в спеку OpenSpec
  (`openspec/changes/.../specs/map-validation`), потом в код.

Ведение работ: OpenSpec (`openspec/`), локальный git без push. Стек: React 19,
`@xyflow/react` v12 (грабли RF v12: у кастомных узлов — явные `style.width/height`;
не ставить `isConnectable={false}` на хэндлы, иначе рёбра не рендерятся).
